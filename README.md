# Cluster — дошка розслідувань кібератак

**Cluster** — студентський вебпроєкт про кібербезпеку у форматі детективної дошки розслідувань.
Кожна «фотографія» на дошці — це справа про певний тип атаки. Справи з'єднані червоними нитками,
а темну дошку можна освітлювати «ліхтариком». У кожній справі є п'ять розділів:

1. Що сталося
2. Як діяла атака
3. Наслідки
4. Як захиститися
5. Навчальні висновки

Сайт статичний: HTML, CSS і Vanilla JS, без бекенду, бази даних і збирання (build).
Його можна одразу розмістити на GitHub Pages.

## Локальний запуск

Дані справ завантажуються через `fetch()`, а браузер блокує такі запити, якщо відкрити
`index.html` напряму (`file://`). Тому потрібен простий локальний сервер. Підійде будь-який з варіантів:

**Python (зазвичай уже встановлений):**

```bash
git clone https://github.com/kirieeleison/cluster.git
cd cluster
python3 -m http.server 8000
```

Відкрийте http://localhost:8000

**Node.js:**

```bash
npx serve .
```

**VS Code:** розширення *Live Server* → «Open with Live Server».

## Як додати нову справу

1. Скопіюйте будь-який файл із `data/cases/` і перейменуйте його, наприклад `data/cases/sim-swap.json`.
   Ідентифікатор може містити лише малі латинські літери, цифри та дефіс.
2. Заповніть поля. Кожен розділ у `sections` має вигляд:
   ```json
   "defense": {
     "text": ["Абзац тексту…"],
     "list": ["Пункт списку…", "Ще пункт…"]
   }
   ```
   Ключі розділів фіксовані: `what`, `how`, `impact`, `defense`, `lessons`. Обидва поля, `text` і `list`, необов'язкові.
3. Додайте фото в `assets/img/cases/` (бажано WebP, 800×600, до 150 КБ) і обов'язково напишіть змістовний `alt`.
4. Додайте справу в `data/cases.json`:
   - у масив `cases`, з позицією на дошці `position: { x, y }` у відсотках;
   - за бажання додайте зв'язки в `links`: пари ідентифікаторів, між якими тягнеться нитка.

HTML і JS змінювати не потрібно.

## Доступність і швидкодія

- **Ліхтарик** вмикається лише на пристроях із мишею або тачпадом. На сенсорних екранах і при
  системному налаштуванні «зменшити рух» дошку одразу підсвічено.
- **«Підсвітити все»** прибирає затемнення. **«Без ефектів»** вимикає ліхтарик і всі анімації.
  Вибір зберігається в браузері.
- Налаштування `prefers-reduced-motion` враховується і в CSS, і в JS.
- Клавіатура: посилання «Перейти до дошки», видиме кільце фокусу, а світло ліхтарика рухається
  за фокусом (Tab).
- Контраст тексту — не менше 4.5:1. Пари кольорів перелічено на початку `css/tokens.css`.
- Швидкодія: системні шрифти (жодних завантажень), `loading="lazy"` для зображень, явні `width`/`height`
  (без стрибків верстки), перемальовування ліхтарика й ниток через `requestAnimationFrame`.
- Ціль Lighthouse (desktop): Accessibility ≥ 90, Performance ≥ 80.
  Перевірка: Chrome DevTools → вкладка **Lighthouse** → Mode *Navigation*, Device *Desktop*.

## Робота в команді з 3 людей

Файли розподілено так, щоб кожна людина працювала у «своїх» папках і конфлікти злиття майже не виникали.

| Роль | Основні файли | Чого не чіпати без домовленості |
|---|---|---|
| **Дизайн** | `css/*.css`, `assets/icons/`, розмітка в `index.html` / `case.html` | назви класів `card__*`, атрибути `data-*` (їх використовує JS) |
| **Інтерактив** | `js/**` | тексти в `data/`, кольори (беріть лише змінні з `tokens.css`) |
| **Контент** | `data/**`, `assets/img/cases/` | HTML/CSS/JS |

Правила, що зменшують конфлікти:

- **Кожна справа — окремий файл.** Двоє людей можуть одночасно писати різні справи.
- **Кольори та розміри задаються лише в `tokens.css`.** Інші файли використовують змінні, тому зміна
  палітри — це правка в одному місці.
- **Контракт між HTML і JS — атрибути `data-*` і класи `card__*`.** Дизайнер може вільно змінювати
  вигляд, доки ці «гачки» на місці.
- **Робота в гілках:** `design/…`, `feature/…`, `content/…` → Pull Request у `main` → швидкий перегляд
  колегою. Робіть невеликі PR і частіше оновлюйтеся з `main` (`git pull --rebase origin main`).
- `.editorconfig` вирівнює відступи та кінці рядків, тому в diff не буде «шуму» через форматування.
